\begin{abstract}
Retrieval-augmented robot control is tempting: retrieve similar prior episodes, condition the policy, and reuse past physical experience. The failure mode is that semantic or visual similarity can be physically incompatible with the current contact mechanism. We study embodied retrieval keys for control, where prior episodes are indexed by contact, support, friction, compliance, and actuation structure rather than language or image proximity alone. A v4.1 local benchmark spans 5 contact-rich tasks, 7 mechanism-shift regimes, 5 corpus/domain splits, 9 methods, 7 paired seeds, 84 rollout episodes per group, 5,880 task/regime/seed stress rows, and 8 documented failure cases. Under combined stress, the proposed mechanism retrieval controller reaches $0.665 \pm 0.008$ success versus $0.562 \pm 0.008$ for the strongest non-oracle baseline, conformal retrieval filtering. The paired success gain is $0.103 \pm 0.005$ with wins on 7/7 seeds. The method also improves mechanism-match precision, lowers incompatible retrievals, reduces damage and query cost, and improves recovery success. This is strong local evidence for a submission rebuild, but not final ICLR-main readiness without real robot or external high-fidelity validation.
\end{abstract}

\section{Motivation}

Generic retrieval works when the retrieved item is relevant to the query. In robot control, relevance is physical. A prior episode may share language labels or visual layout while differing in support topology, friction, compliance, actuation lag, or recoverability. Conditioning a controller on that episode can make the policy more confident and more wrong.

This paper tests a narrow claim: retrieval for embodied control should be keyed by mechanism compatibility. The proposed controller retrieves prior episodes whose physical mechanism matches the current action context, rejects counterfactual-incompatible memories, and triggers a recovery controller when the retrieved mechanism predicts a failure mode.

\section{Mechanism Retrieval Controller}

For a query state $x$, candidate action $a$, and episode memory $e_i$, the controller scores
\[
s_i(a,x) =
\phi_{\mathrm{mech}}(x,a)^\top \phi_{\mathrm{mech}}(e_i)
- \lambda\, \widehat{\Delta}_{\mathrm{counterfactual}}(a,x,e_i)
- \gamma\, \widehat{u}_{\mathrm{cal}}(x,e_i),
\]
where $\phi_{\mathrm{mech}}$ represents contact/support/friction/compliance/actuation structure, $\widehat{\Delta}_{\mathrm{counterfactual}}$ estimates whether the retrieved episode would recommend a physically incompatible action, and $\widehat{u}_{\mathrm{cal}}$ calibrates mechanism-match uncertainty. Retrieval context is passed to the controller only if it clears the compatibility gate; otherwise the policy falls back to conservative control or recovery.

\section{Benchmark}

The benchmark includes drawer pulling with stiction, peg insertion, cable routing, cloth sliding, and force-limited lid twisting. Mechanism regimes include source-matched control, friction mismatch, support-topology shift, compliance shift, occluded-contact shift, actuator-lag shift, and compound mechanism shift. Corpus/domain splits range from seen-corpus retrieval to combined stress.

Baselines cover no retrieval, language episode retrieval, visual nearest retrieval, state-nearest memory, retrieved-context behavior cloning, uncertainty-gated retrieval, conformal retrieval filtering, the proposed mechanism retrieval controller, and an oracle mechanism retrieval upper bound.

\section{Failure Cases}

The failure-case audit records eight boundaries: language-near but mechanism-wrong retrieval, hidden support topology, actuator lag plus compliance, visually near but mechanically opposite episodes, stale recovery memories, partial-observability aliases, overconformal rejection, and remaining oracle headroom under compound shift. These cases require active contact evidence, embodiment-age checks, active disambiguation, and robot or independent high-fidelity validation before this can be treated as a submission-ready control system.

\section{Related Work Boundary}

Retrieval-augmented generation retrieves text or examples for reasoning systems \citep{ragtechnical2025,ragbiomed2025,uavrag2025}. The embodied setting changes the unit of relevance: physically compatible episodes matter more than semantically similar episodes. Episodic robot memory and retrieval-conditioned imitation learning are adjacent, but this paper isolates mechanism compatibility as the retrieval key for contact-rich control.

\section{Limitations And Submission Decision}

The evidence is local and generated by the released benchmark. It is stronger than the archived scaffold but still lacks real robot experiments, external high-fidelity simulator transfer, released retrieval corpora, and trained controller checkpoints. The honest terminal state is therefore \textbf{STRONG\_REVISE}: the idea is worth rebuilding aggressively, but it is not yet ICLR-main ready.
